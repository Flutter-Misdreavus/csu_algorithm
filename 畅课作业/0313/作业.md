## 1. 对于二分查找来说有一个基本前提是有序。请问对于长度为n的查找表，至少要做多少次二分查找，才能使其性能相对于顺序查找更优？

**答：至少需要约 log₂n 次查找**

假设查找表长度为 n，进行 k 次查找：

- 顺序查找总成本：$T_{seq} = k \cdot n$
- 二分查找总成本：$T_{bin} = T_{排序} + T_{查找} = n \log n + k \log n$
  - 其中 $n \log n$ 是排序预处理成本（比较排序）
  - $k \log n$ 是 k 次二分查找的成本

要使二分查找更优，需要满足：
$$T_{bin} < T_{seq}$$
$$n \log n + k \log n < k \cdot n$$

移项整理：
$$n \log n < k \cdot (n - \log n)$$

解出 k：
$$k > \frac{n \log n}{n - \log n}$$

当 n 较大时，$\log n \ll n$，因此：
$$n - \log n \approx n$$

于是：
$$k > \log_2 n$$

**结论**：至少需要进行约 $\log_2 n$ 次查找，二分查找（含排序成本）才开始优于顺序查找。

## 2. 给出三分查找的实现策略，并对比分析与二分查找各自的应用场景。

**答：**

**一、三分查找实现策略**

三分查找将搜索区间分成三部分，通过两个分割点缩小搜索范围。

```
算法步骤：
1. 初始化搜索区间 [left, right]
2. 计算两个分割点：
   m1 = left + (right - left) / 3
   m2 = right - (right - left) / 3
3. 比较目标值 target 与 arr[m1]、arr[m2]：
   - 若 target == arr[m1]，返回 m1
   - 若 target == arr[m2]，返回 m2
   - 若 target < arr[m1]，搜索区间缩小为 [left, m1-1]
   - 若 target > arr[m2]，搜索区间缩小为 [m2+1, right]
   - 否则，搜索区间缩小为 [m1+1, m2-1]
4. 重复步骤2-3，直到找到目标或 left > right
```

时间复杂度：$O(\log_3 n) \approx O(0.63 \log_2 n)$
空间复杂度：$O(1)$

---

**二、二分查找 vs 三分查找 对比分析**

| 特性 | 二分查找 | 三分查找 |
|------|---------|---------|
| 分割方式 | 均匀分成2部分 | 均匀分成3部分 |
| 时间复杂度 | $O(\log_2 n)$ | $O(\log_3 n)$ |
| 每次比较 | 1次 | 2次 |
| 常数因子 | 较小 | 较大 |
| 实际效率 | **更快** | 稍慢 |

**实际比较次数分析**：
- 二分查找：约 $1 \times \log_2 n$ 次比较
- 三分查找：约 $2 \times \log_3 n = 2 \times \frac{\log_2 n}{\log_2 3} \approx 1.26 \times \log_2 n$ 次比较

---

**三、各自应用场景**

**二分查找适用场景**：
- ✓ 有序数组的标准查找
- ✓ 查找第一个/最后一个满足条件的元素
- ✓ 二分答案问题
- ✓ 边界值查找
- ✓ 整数域上的优化问题

**三分查找适用场景**：
- ✓ 单峰/单谷函数的极值求解
- ✓ 凸函数/凹函数的优化问题
- ✓ 实数域上的函数求极值（三分法更直接）
- ✓ 当函数性质较好时，三分可更快收敛

---

**四、结论**

| 场景 | 推荐算法 |
|------|---------|
| 整数有序数组查找 | 二分查找 |
| 二分答案问题 | 二分查找 |
| 单峰函数求最大值 | 三分查找 |
| 单谷函数求最小值 | 三分查找 |
| 凸函数/凹函数优化 | 三分查找 |

**总结**：一般情况下，二分查找效率更高，是有序查找的首选；当涉及函数极值求解时，三分查找更直接、自然。
